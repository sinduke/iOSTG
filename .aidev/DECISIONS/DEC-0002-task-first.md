# DEC-0002：Task 必须先于实施独立落盘

```yaml
id: DEC-0002
status: DECIDED
recording_mode: contemporaneous
decided_at: 2026-08-13
authority: maintainer
supersedes: null
```

## 背景

TASK-0001 虽然最终包含目标、范围和证据，但 Task 文件与其实施文件在同一次修改中产生。它没有成为执行开始前可以独立恢复的检查点，因此未能真正防止长任务中途丢失收敛信息。

## 决定

任何会修改项目状态的实施工作，都必须先有一个由维护者接受、独立落盘并重新读取确认的 Task 文件。只有完成这个检查点后，Agent 才能进入 `in_progress` 并执行其他修改。

## 必须成立

- 顺序固定为“完成收敛 → 生成 Task → 维护者接受 → Task 独立落盘 → 重新读取 Task → 开始实施”。
- Task 和实施修改不能在同一个文件修改步骤中首次出现。
- Task 至少保存目标、范围、非目标、权限边界、完成条件、必要来源和交接入口。
- 任务大小和预计耗时不改变该规则；小任务也可能演变成长任务。
- 执行中发现新范围时，先暂停，再修订 Task revision 或创建新的已接受 Task。
- Agent 中断或被替换后，新 Agent 从 Task、当前 diff 和 Evidence 接续，不重新猜测原始意图。

## 例外边界

纯问答和只读分析可以使用 `Quick` 模式，不要求 Task。一旦准备修改仓库文件、Git 状态、工程配置或外部系统，必须先进入已接受 Task。

## 影响

- TASK-0001 保留为一次真实过程偏差，不静默改写成正确演练。
- TASK-0002 是第一条按 Task-first 顺序执行的任务。
- 将来可以用工具检查 Task 是否先于其他变更存在，但本决定不预先指定 CLI 或实现方式。
